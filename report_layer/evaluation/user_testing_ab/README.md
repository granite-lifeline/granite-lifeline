# Report Layer user-testing stimuli

Five named Seat Leon CSV trips are processed together by Data Layer, then
once by Model Layer. The saved Model output is used to generate the report.

**Design update:** the original goal here was a blind RAG vs. no-RAG
comparison (conditions "A"/"B", generated by run_user_testing_ab.py). A real
run on this same Model output showed the comparison itself is not reliably
one-directional — RAG's retrieved knowledge doesn't always end up more
specific in the final text than the model's own trained knowledge, because
Layer 2's current prompt treats retrieved knowledge as a list to *choose
from* rather than something to reason *with*. That's a real prompt-design
gap (being addressed separately), not a finding worth building a user study
on. The final user testing therefore does not compare conditions — it uses
only the RAG (owner_safe_rag / condition "B") report and tests readability.

run_user_testing_ab.py, condition A, and administrator-condition-key.json
are kept for reproducibility of that investigation, not as the current
testing design. The "A"/"B" labels never appeared in the Dashboard UI itself
— they only exist in this directory's file names and the admin-only key.

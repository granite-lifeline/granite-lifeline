Task:
Write the recommended_action section for a diagnostic report.

Rules:
- Return 2 to 4 clear action items.
- Actions must be practical for a vehicle owner.
- Use retrieved action guidance as the main source for recommended actions.
- Treat the input context as the main source of truth. If retrieved action guidance conflicts with the input context, follow the input context.
- Match retrieved actions to the current risk_level and key signals.
- If retrieved action guidance is missing or says no specific action guidance was found, give safe general monitoring or inspection advice.
- If audience is "non-technical vehicle owner", use plain language for a vehicle owner without automotive expertise.
- Avoid unexplained technical jargon.
- If a technical term is necessary, explain it in simple words.
- Make every action concrete and specific.
- Do not use vague advice such as "check related components".
- Say what the owner should actually do, such as "take your car to a mechanic to check the cooling system".
- Match the urgency to risk_level:
  - Low: suggest monitoring and simple checks.
  - Medium: suggest checking the vehicle soon.
  - High: suggest prompt inspection and avoiding heavy driving if safe.
- Match wording strength to prediction_confidence:
  - Higher confidence: use more specific, action-oriented wording.
  - Lower confidence: use more observational wording and suggest monitoring.
- For Low risk, do not recommend urgent repair or replacement unless
  the context contains a strong abnormal signal. Prefer monitoring,
  rechecking after more driving, and simple visual checks.
- Follow certainty guidance for wording strength, but never say the system has confirmed a real fault.
- Do not cause unnecessary panic.
- Do not recommend unsafe actions.
- If there is not enough evidence, recommend monitoring and collecting more data.
- If the context includes a Failure Projection section, use only the
  failure probability or estimated cycles that are actually present.
  Do not invent missing probability, cycle count, dates, mileage, or
  deadlines.
- If estimated_failure_probability is present but
  estimated_cycles_to_failure is missing, do not say there is "no
  failure probability". Say no cycle estimate is available. If the
  probability is very small, describe it as a very low model-estimated
  probability of crossing the High-risk threshold, not as a calibrated
  probability of mechanical failure.
- If Model Layer Notes mention "forwarded from Data Layer
  proxy_decisions.csv" or "Data Layer proxy decision", keep actions
  consistent with rule-based proxy evidence: recommend inspection or
  diagnostic confirmation, but do not treat the proxy note itself as a
  confirmed mechanical failure.
- If the current key signals are mostly NORMAL, avoid recommending
  immediate part replacement. Ask for confirmation with a scan tool or
  mechanic inspection first.
- If the context includes Model Layer Notes, use them only to explain
  provenance or data-quality limits when helpful. Do not turn notes
  into mechanical repair actions.

Good example (intake_air_temperature_sensor_fault,
Medium risk):
[
  "Check the intake air temperature sensor, which is usually located
near the air filter box or in the intake tube. Look for loose
connections or damaged wiring.",
  "If you recently drove in very hot weather or heavy traffic, let

soak (trapped engine heat) can affect sensor readings.",
  "Ask a mechanic to inspect the sensor wiring and connector for
corrosion or damage before replacing the sensor itself.",
  "If the issue persists, tell the mechanic that the intake
temperature sensor is reading outside its normal range, so they can
test the sensor and wiring with a diagnostic tool."
]

Why this works:
- Explains where to find components (near air filter box or intake
  tube)
- Provides context-specific advice (cold-start plausibility,
  stuck or slow sensor response, wiring checks)
- Tells owner what to say to mechanic (intake temperature sensor
  reading abnormal)
- Matches Medium risk urgency (check soon but not emergency)
- Actions are concrete and specific for a vehicle owner

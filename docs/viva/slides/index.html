D1

Continuity-aware cleaning

Turn irregular OBD-II recordings into 1 Hz evidence without inventing continuity across missing time, invalid samples or recording boundaries.

ADR 101 · ACCEPTED
Raw source identityFilename date + in-file time; stable chronological file order.
UTC timelineLocalise in Europe/Berlin, sort timestamps and keep the last duplicate.
Trip → segmentsA raw gap greater than 3 seconds starts a new continuous segment.
Segment-safe 1 Hz gridResample each segment independently; fill only complete gaps of at most 2 seconds.
Continuity blocksBreak again wherever quality, trip, segment, row or 1-second cadence fails.
THE THREE IDENTITIES — NOT INTERCHANGEABLE
  • trip_id identifies one source driving record. It preserves provenance and groups segments that came from the same file.
  • segment_id identifies raw recording continuity inside a trip. It changes when the observed timestamp gap is >3 s.
  • continuity_block_id is stricter downstream eligibility. It also breaks on invalid quality, a missing/flagged sample, a non-consecutive row, or a timestamp step other than exactly 1 s.
  • Therefore “same trip” does not mean “safe rolling window”, and even “same segment” does not guarantee that every row is eligible.
CURRENT CLEANING AND QUALITY LOGIC
  • _parse_timestamps() combines filename date with source time, localises it, and emits UTC.
  • Hard-invalid values outside physical bounds become missing values, but their origin remains visible through per-signal flags.
  • Suspicious yet physically possible values are retained and flagged; the cleaner does not silently rewrite uncertain evidence.
  • Cross-field rules mark contradictions such as RPM=0 while speed>0, MAF=0 while RPM>0, and sub-zero coolant in warm ambient conditions.
  • _resample_segment() creates row_in_segment, source-sample counts and observed-sensor counts on the 1 Hz grid.

Why crossing a boundary would invalidate later results
  • Interpolation: could invent a smooth transition across an unobserved stop, restart or logging outage.
  • Rolling features and slopes: could compare sensor values that were not adjacent in real time.
  • Persistence logic: could count evidence on opposite sides of a gap as one continuous event.
  • Model windows: could present a synthetic 512-step history assembled from separate operating periods.
  • Evaluation: could overstate usable coverage and create false confidence in planted-fault detection.
Exact downstream admission rule
  • build_quality_valid_mask() admits a signal only when its value exists and its imputed, suspicious and hard-invalid flags are explicitly false. Missing flags are treated conservatively as invalid.
  • build_continuity_blocks() continues a block only when current and previous samples are valid, trip and segment match, row_in_segment increments by one, and timestamps differ by exactly one second.
  • Recorded break reasons are dataset_start, invalid_sample, trip_boundary, segment_boundary, previous_sample_invalid, row_not_consecutive and timestamp_not_consecutive.
  • strict_window_mask(), strict_elapsed_span_mask() and strict_event_neighborhood_mask() reuse this shared rule. A 180-second elapsed span requires 181 valid endpoints.
Rejected alternatives and trade-offs
  • One file = one continuous trip: simple, but demonstrably false for the source corpus.
  • Concatenate all records: rejected because vehicle sessions and time gaps would disappear.
  • Keep only trip_id: rejected because downstream code could not distinguish separate continuous sections.
  • Drop every row after a large gap: rejected because valid evidence after the gap would be lost; a new segment preserves it safely.
  • Interpolate every gap: rejected because long gaps cannot be justified as observed vehicle behaviour.
  • Trade-off: strict boundaries reduce coverage near gaps, but make every admitted temporal feature auditable. The 3 s and 2 s thresholds remain dataset-specific rather than universal physical constants.

WHY NOT TRAIN A FAULT CLASSIFIER?
  • The 81 source trips record ordinary driving, but none has a mechanically verified fault or repair outcome to supervise a classifier.
  • Data proxy outputs are physical rules, not real labels. Training on them and evaluating against them would be circular.
  • A classifier head would learn to reproduce thresholds such as overheating, not independently recognise physical degradation.
  • A custom LSTM from scratch would need to learn normal dynamics from a small single-vehicle dataset without TTM's broad pretraining.
  • Forecasting can learn from quality-gated ordinary-driving sequences: expected continuation is predicted, and unexpected deviation becomes the signal.
EXACT FORECAST IMPLEMENTATION
  • run_ttm_forecast() converts the six context channels to float32 and normalises each channel within the current window.
  • get_model() loads the committed ttm_finetuned_e5_lr5e-5/model artefact with context=512 and prediction=96.
  • Inference runs in eval() and torch.no_grad(); the output is checked for exactly 96 timesteps and six signals.
  • The prediction is transformed back to original units before comparison with the observed future.
  • calculate_residuals() uses absolute error; summarize_residuals() records mean and maximum error for each signal.

How residual evidence remains independent from proxy rules
  • TTM never receives anomaly_type, DTC or proxy result as a training target.
  • Its task is only to forecast six observed time series from their previous values.
  • The frozen fine-tuning split uses quality flags and confidence only; decision-level proxy outputs do not define its split or loss.
  • Controlled synthetic injections provide the evaluation key after training; they are not training targets.
  • This provides some separation between “Data's physical rule fired” and “the temporal continuation was difficult for TTM to predict.”
  • Evaluation is still limited by synthetic proxies because no real faults exist; independence reduces circularity but cannot create missing ground truth.
Why window normalisation is necessary—and its limitation
  • RPM, speed, temperature and airflow have very different units and numerical scales; direct tensors would let large-magnitude channels dominate.
  • Per-window mean/std places the six signals on comparable numerical scales for the forecaster.
  • A channel with std below 1e−6 uses 1.0 to prevent division by zero.
  • Predictions are denormalised before residuals are reported, so evidence returns to RPM, km/h, °C, kPa, g/s and percent units.
  • Because normalisation is window-local, residual magnitude still needs reference-range scaling before it becomes a cross-signal risk score.
What a high residual means—and what it does not
  • It means observed future behaviour differed from TTM's expected continuation under that context.
  • It may indicate degradation, but can also reflect unusual baseline-compatible driving, distribution shift, missing-data handling or forecast error.
  • Residuals therefore become risk evidence, not calibrated failure probabilities.
  • Component attribution requires physically informed scoring and key-signal context in the next node.
  • A fixed rule can identify an already crossed boundary; a residual may provide an earlier leading indicator, but this project has not measured real lead time.

How prediction confidence is calculated
  • For Model-scored results, the six normalised residual scores are compared; confidence is 1 − std(scores), clipped to 0.35–0.95.
  • Top key signals remain the three largest TTM residual channels.
  • The rule-only pedal score is deliberately excluded from residual-spread confidence because TTM forecast spread did not create it.
  • A winning forwarded verdict uses Data confidence instead: high→0.9, provisional→0.6, low→0.35; any low-confidence cap forces 0.35.
  • Where multiple proxy rows support one verdict, the weakest confidence is reported conservatively.
Risk levels and the provisional threshold evidence
  • Low: risk <0.4129—record only.
  • Medium: 0.4129≤risk<0.9—raise an inspection alarm.
  • High: risk≥0.9—priority inspection; 0.9 is a conservative presentation boundary, not 90% failure probability.
  • 0.4129 was selected on eight calibration segments by maximising macro F1 subject to baseline-control FPR≤0.10; calibration FPR was 0/8.
  • On three held-out baseline segments FPR was 1/3, and the full 11-segment baseline-control FPR was 1/11 (9.09%). The policy is correctly marked provisional_synthetic_only.
Grain mismatch and forwarding limitation
  • Data decisions may be trip-, episode- or segment-scoped; Model outputs one result per 608-row detector window.
  • Trip/episode decisions therefore apply to every Model window in that trip; segment-first-row decisions are restricted to the named segment when available.
  • This preserves usable integration but cannot precisely localise every decision to one 96-second future window.
  • Every forwarded result adds a note naming Data provenance, sub-check IDs, DTC and confidence so Report does not mistake it for TTM scoring.

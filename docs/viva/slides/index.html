Data Layer — Full Pipeline Detail
Lei Pei · Qiuting Fu
Full Pipeline Detail
  • Ingest & clean — 81 trip CSVs resampled to a uniform 1 Hz grid; a two-level range policy per signal (physical range vs. tighter suspicious range) repairs impossible values but keeps merely-unusual ones, flagged not deleted — deleting the unusual would delete the anomalies we're hunting.
  • Operating-condition labelling — a two-level state machine (thermal state × kinematic state) tags every second, segment-bounded with a 3s jitter cleanup. Result: 77.85% post-warmup / 18.63% warm-up / 3.51% engine-off, ~96.5% high-confidence.
  • Feature engineering — a staged, contract-validated chain (input validation → atomic features → engine-start context → windowed → calibrated → production assembly). Thresholds are frozen in a calibration registry, never re-fitted on new data.
  • Proxy evidence & decision — rule-state builder → event evidence → duration evidence → decision builder. Every row logs a full audit trail (proxy_id, result_state, decision_role); only a permitted "verdict" row can emit a diagnostic code.
Deep Dive: Proxy Label Design
  • Condition-stratified, not global — each check runs only in its matching state, threshold calibrated just outside the healthy envelope observed in that state:
    • Slow warm-up (P0128) — ambient-scaled time budget; 20/51 qualified starts trigger, 0/20 healthy false positives.
    • Overheating (P0217) — ≥105°C for ≥180s; healthy max observed was 101°C, longest healthy episode 87s.
    • MAF under-read (P0101) — residual < −18.5 g/s for ≥10s at high load; longest healthy run was 3s (7s headroom).
    • Redundant pedal disagreement (P2138) — 66/66 trips evaluated, zero healthy triggers.
  • Persistence beats single spikes — a check only fires if the condition holds continuously (e.g. ≥30s), or recurs in 3 of the last 4 events — the real mechanism behind "majority voting." This is what defeats 1 Hz sensor noise.
  • Abstain, don't guess — missing signals or out-of-domain data return not_evaluable with a reason, never a forced normal/abnormal verdict.
  • Arbitration — when two sensors disagree (MAF vs. MAP), an independent witness signal decides which side is blamed, or an un-isolated fault code is reported rather than guessing.
Limitations
  • Zero false positives proves specificity, not recall. Fault-injection validation (Stage 4) is still open/TBD — we haven't yet proven a real fault would trip these checks.
  • Proxies indicate, they don't isolate — e.g. slow warm-up points at the thermostat but can't exclude a sensor fault.
  • One car, low-rate, short logs — all thresholds are calibrated on a single vehicle at 1 Hz; some persistence margins are only a few seconds.
  • Some checks were dropped, not hidden — e.g. stuck-MAF and single-channel pedal-freeze checks were found infeasible on this dataset and documented as non-executed, not forced through.
  • With more time: run fault-injection early rather than last, seek an externally labelled fault dataset, and test transfer on a second vehicle.
Model Layer — Full Pipeline Detail
Ray Wang · Lucca Zhou
Full Pipeline Detail
  • Load — consume the Data Layer's clean, contextualised time-series contract. The shared interface now names production_features.csv; some Model code still references the earlier feature_dataset.csv, so filename/version alignment remains an integration cleanup item.
  • Validate input — required fields must be present and numeric. Physically impossible values are repaired or rejected; unusual-but-possible values are retained because they may be genuine anomalies. If more than 5% of a required column is impossible, the input is rejected.
  • Window selection — only unbroken stretches of at least 700 seconds qualify; a 512-second context plus 96-second future never crosses a trip or recording break.
  • Forecast — Granite TTM zero-shot predicts 96s of six readings (rpm, speed, coolant, MAP, MAF, TPS) from 512s of context.
  • Gap measurement — compute |actual − predicted| per signal and normalise residual summaries against healthy reference ranges so signals with different units can be compared.
  • Attribution and risk — deliberately hybrid, not TTM-only. Residual evidence is combined with coolant slope, MAF–MAP cohesion and dual-pedal disagreement; the highest candidate becomes the named anomaly type.
  • Output — anomaly type, risk score (0–1), Low/Medium/High level, confidence, key signals and notes, format-checked by validate_output.py. Failure-horizon fields remain null in the committed sample.
Deep Dive: TTM Architecture
  • Why not a classifier? — all 81 source trips are healthy, so there are no verified fault examples to learn from. Training on Data Layer proxy labels and evaluating against the same rules would be circular: the model would reproduce the answer key instead of independently detecting change.
  • What TTM is — Granite TTM ("Tiny Time Mixer," ibm-granite/granite-timeseries-ttm-r2) is a pre-trained numerical time-series forecaster, not a language model and not a direct component classifier.
  • Why residuals help — TTM predicts a normal continuation. When reality is no longer a typical continuation, the gap grows. That gap is independent evidence of unexpected behaviour; physical features are still required to name the likely system.
  • Healthy-only fine-tuning — trips, not rows, were split to prevent leakage. On 492 held-out windows from 16 trips, overall MAE fell from 55.1951 to 53.0320 (3.919%); all six signals were non-worse, but the result missed the pre-declared 5% threshold for a clear win.
Limitations
  • No verified Model-level real-fault recall. The completed 126-observation synthetic campaign validates the Data Layer's frozen proxy checks. The Model viva document still contains placeholders for Model-level planted-fault precision/recall, so those 126 observations must not be presented as TTM accuracy.
  • Risk is not a learned failure probability. It is a reproducible combination of normalised residuals and physical thresholds; confidence reflects residual consistency, not calibrated field probability.
  • One car, one driver — the healthy baseline and alarm levels are calibrated on a single vehicle's data; no evidence yet that it transfers to another car without re-calibration.
  • Coverage and versions are not fully aligned — the detector actively scores cooling, intake and accelerator-pedal paths while other listed types remain zero-score placeholders; the shared interface has evolved beyond some Model README/code references.
  • Top-one output hides ambiguity — only the highest candidate is exposed even when candidates are close or multiple faults coexist. A ranked list is future work.
  • With more time: run the complete detector over controlled gradual perturbations, test on labelled broken-vehicle data, expose ranked candidates, and evaluate a second vehicle.
